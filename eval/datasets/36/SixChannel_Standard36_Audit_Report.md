# 六经辨证标准 36 例研发测试集：重建与逐例审核报告

> 审核类型：研发侧内容预审与来源一致性检查。**不等于执业中医专家盲审，也不构成医学临床金标准。**
> 本轮没有调用医学大模型、未执行在线临床评测、未修改项目源码或知识库。

## 1. 需求、范围与核验基线

- 输入：`cases_detailed(2).jsonl`（48例）及 `SixChannel_Benchmark48_Review(2).xlsx`。
- 每种病按六经六类解释，重新建立 **太阳、阳明、少阳、太阴、少阴、厥阴各 6 例**，共 36 例。
- 全部 `difficulty=standard`，每例恰有一个主参考六经、一个具名参考方证。
- 经典原文、方证名称、编号、鉴别规则经固定 `grit11/six-channel-agent` 知识库 V1.2 核对。
- 知识库对应 GitHub 提交：`2c92be751fc7574b86812c97d0f34e69f000e2b5`。
- `label_type=silver_reference_pending_expert_review`，任何案例均未声称专家终审通过。
- 来源：<https://github.com/grit11/six-channel-agent/tree/2c92be751fc7574b86812c97d0f34e69f000e2b5/knowledge/v1.2>；公开对照：<https://ctext.org/shang-han-lun/zhs>。

## 5. 三类需要优先请专家判断的标签

| 新编号 | 当前银标 | 真实来源与具体疑问 | 专家不认可时 |
|---|---|---|---|
| STD019、STD020 | 太阴 / 理中丸 | 第386条可对应寒性吐利、寒多不欲饮水，但其条文属于霍乱部分；“太阴”是结合第273、277条归纳得来 | 改写为第279条有直接归属的高质量案例，或将本例放到跨条文推定专项，不在严格单经集计分 |
| STD018 | 少阳 / 柴胡桂枝汤 | 第146条对应少阳兼表证，是否允许使用单一少阳参考而不增加太阳须确认 | 若应为双经，移出标准单经集并换入更纯的少阳病例 |
| STD036 | 厥阴 / 吴茱萸汤 | 第378条处于厥阴相关条文，但吴茱萸汤也有其他章节对应，须判断本例是否可采用单经参考 | 若不能，采用更明确的厥阴来源案例替换 |

**额外注意：** 原知识库 398 条经典、128 个方证、53 个鉴别规则本身的 `review_status` 中仍存在需要专家最终批准的记录。因此任何银标在独立专家签字前只能称为研发参考，不可称“临床真值”。

## 6. 技术一致性核验

执行命令：
```powershell
conda run -n langgraph python validate_standard36.py SixChannel_Standard36_Silver_v1.jsonl
```

已完成的离线核验：
- 36/36 条记录可解析为 JSON；ID 全局不重复，原始患者文本不重复。
- 六经每类恰好6例，全部 standard，reference_channels 每行恰好一条且和组别匹配。
- reference_formulas 每行恰好一个具名方证；至少包含对应方证的 `formula_pattern` Evidence ID 与一条 `classic_clause` Evidence ID。
- source_refs 的知识版本统一为 `1.2`；原文没有直接出现拟定方名，避免最明显的答案泄漏。
- 主要方证来源的 `source_clause_nos` 与每例所列经典条文号至少有一处交集；鉴别规则 ID 可回查。
- `expected_unknown=[]`、`conflicted_keys=[]`、`expected_relation=single`；本版暂时不考核含混、矛盾和复杂传经。

**本轮没有运行模型在线精度实验。** 因而不能宣称这版取得了任何 Top-1 / Top-3 医学准确率提升；输入更明确也可能使难度分布改变，不能把新36例与旧48例的分数直接横向比较。

## 7. 数据集文件与专家盲审流程

- `SixChannel_Standard36_Silver_v1.jsonl`：新36例、沿用原 JSONL 字段契约，可被现有 `eval/v2_online_eval.py` 读取。
- `SixChannel_Standard36_Review_v1.xlsx`：36例完整参考标签，原48例逐条审查，所有保留和优化追溯，重点鉴别对照及审核边界。
- `SixChannel_Standard36_ExpertBlind_v1.xlsx`：只向医学专家提供盲审编号与病历文本，不包含原参考六经、方证和来源注释；用于独立判断。
- `SixChannel_Standard36_blind_mapping.csv`：**仅项目负责人保管**，将专家盲审编号与 STD 编号匹配。不要与盲审文档同发给专家。
- `validate_standard36.py`：离线结构与 Evidence ID 一致性校验，不调用模型。
- `SixChannel_Standard36_manifest.json`：主库提交、输入和输出数据哈希、病例覆盖情况、审核状态。

盲审建议：先由执业中医专家在无答案的工作簿中独立标注六经与方证；以“可唯一判断、需补问、不能唯一判断”区分情况；对上述高风险条目优先复核；不通过的病例重新改写或替换后另存版本；终审签字后才锁定为可用于模型对照的专家标签。

## 8. 实验版本管理及下一步

1. 此前第一阶段的模型测试不能倒推“银标错误”或自动替换标签，数据审核与模型优化应独立开展。
2. 本版36例相较旧48例，题目数量与难度、参考标签完整度均变化。可在固定模型配置下执行新36例测试，但只报告本数据集内部结果。
3. 数据集参考标注继续叫“研发银标”；待专家盲审通过后另行生成 `v1_expert_approved`，保留该版 SHA 以防止数据漂移。
4. 没有用户审批前，本次**不推进双路融合阶段**，也不修改 V2.1 的 S1–S4 推理代码。
